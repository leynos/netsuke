# 🧵 Netsuke

[![Ask DeepWiki](https://deepwiki.com/badge.svg)](
https://deepwiki.com/leynos/netsuke)

*親しみやすいビルドシステムコンパイラです。YAMLとJinjaを入力に、Ninjaを出力します。*

Netsukeは読みやすい
`Netsukefile`を検証済みの静的なNinjaビルドグラフへと変換します
。動的な作業は高レベルのマニフェストに留め、高速なインクリメンタル実行は
[Ninja](https://ninja-build.org/)に任せます。

ウェブサイト:<https://df12.studio/netsuke>

______________________________________________________________________

## なぜNetsukeなのか

- **読みやすいマニフェスト**:タブ依存の言語ではなく、YAMLでルール、ターゲット、依存関係、デフォルトを記述します。
- **動的なプランニング**:Netsukeがビルドグラフを作成する前に、Jinjaの変数、マクロ、
  `foreach`、`when`、グロブを利用します。
- **静的な実行**:ビルドコマンドを実行する前に、生成されたNinjaファイルを検査したりグラフを描画したりできます。
- **有用な診断**:ソースを認識したエラー、ローカライズされた出力、進捗報告、そして正規の
  `--json`機械可読なコマンド出力が得られます。
- **特定のツールチェインに縛られない**:Rust、C、Python、Webプロジェクト、その他コマンドでビルドできるものすべてに同じマニフェストモデルを使用できます。

## クイックスタート

### 前提条件

Netsukeは現在、以下を必要とします:

- `PATH`上に[Ninja](https://ninja-build.org/)があること、
- ソースからインストールする場合は、[`rust-toolchain.toml`](rust-toolchain.toml)
  で固定された日付指定のRust
  nightlyツールチェインが必要です(チェックアウト内では
  `rustup`が自動的にインストールします
  )。NetsukeはPoloniusボローチェッカーを使ってビルドされます。これはnightlyでデフォルトで有効になっており、安定版になるまではnightly限定です。詳細は
  [ADR-006](docs/adr-006-adopt-polonius-nightly-toolchain.md)
  を参照してください。

### インストール

最新の公開プレリリースはNetsuke v0.1.0-beta3です。crates.ioから入手できます。
[`cargo binstall`](https://github.com/cargo-bins/cargo-binstall)
が利用可能な場合は、それを優先してください。ビルド済みのリリースバイナリを取得でき、以下のツールチェイン要件を回避できます。

```sh
cargo binstall netsuke-build
```

代わりにレジストリからビルドする場合は、リポジトリのチェックアウト外で実行されるため、固定されたツールチェインは自動的には使用されません。明示的に選択してください:

```sh
rustup toolchain install nightly-2026-08-23
cargo +nightly-2026-08-23 install netsuke-build
```

ビルド済みのインストーラーは
[v0.1.0-beta3 GitHubリリース](https://github.com/leynos/netsuke/releases/tag/v0.1.0-beta3)
から入手できます:

| プラットフォーム | アーキテクチャ                          | パッケージ                       |
| ---------------- | --------------------------------------- | -------------------------------- |
| Linux            | x86-64(`amd64`)およびArm64(`arm64`)     | Debian(`.deb`)およびRPM(`.rpm`)  |
| macOS            | Intelのx86-64およびApple siliconのArm64 | インストーラーパッケージ(`.pkg`) |
| Windows          | x64およびArm64                          | Windowsインストーラー(`.msi`)    |

Linuxパッケージは
`netsuke`のマニュアルページをインストールし、`ninja-build`を依存関係として宣言します
。macOSまたはWindowsのインストーラーを使用する場合は、Ninjaを別途インストールする必要があります。Windows版のMSIは
`C:\Program Files\netsuke`にインストールされ、`PATH`は更新されません
。単体バイナリおよび同梱のヘルプとライセンスファイルにはSHA-256チェックサムファイルが付属します。v0.1.0-beta3の時点で、インストーラーパッケージにはチェックサムの付属ファイルはありません。プラットフォーム別のコマンドとWindowsのセットアップについては、
[ユーザーズガイド](docs/users-guide.md#install-netsuke)を参照してください。

現在のソースチェックアウトをCargoでインストールするには:

```sh
git clone https://github.com/leynos/netsuke.git
cd netsuke
cargo install --path .
```

### 最初のビルド

新しいディレクトリを作成し、`Netsukefile`という名前のファイルを追加します:

```yaml
netsuke_version: "1.0.0"

targets:
  - name: hello.txt
    command: "echo 'Hello from Netsuke!' > hello.txt"

defaults:
  - hello.txt
```

Netsukeを実行し、結果を確認します:

```sh
netsuke
cat hello.txt
```

2番目のコマンドは`Hello from Netsuke!`を出力します。変数、テンプレート、
`foreach`については[クイックスタートガイド](docs/quickstart.md)
を参照し、パス、コレクション、ファイルシステム、時刻、コマンド、環境、グロブ、ネットワークの各ヘルパーについては
[テンプレート標準ライブラリガイド](docs/stdlib-yaml-and-jinja-guide.md)
を利用してください。

## 現在できること

Netsuke v0.1.0-beta3のコアとなるビルドシステムコンパイラは、以下を提供します:

- 重複キーとスキーマの検証を伴うYAML 1.2マニフェストの解析、
- Jinjaの変数、マクロ、`foreach`、`when`
  、グロブ、環境ヘルパー、実行ファイルの検出、オプトインのネットワークヘルパー、
- 再利用可能なルール、ターゲット、アクション、デフォルト、および明示的・暗黙的・順序のみの依存関係、
- `netsuke help targets`によるターゲットとアクションの検出
  (レシピを描画しない条件付きエントリを含む)、
- 重複出力・ルール欠落・循環のチェックを備えた決定的な中間ビルドグラフ、
- デフォルトでWindows PowerShellを介したWindowsのレガシーレシピ実行(明示的なGit
  BashまたはMSYS2互換ルートあり)、
- Ninjaの生成と実行、および`clean`と単体のマニフェスト生成、
- Graphviz
  DOTまたは自己完結型でアクセシブルなHTMLとして再現可能な依存関係グラフ、
- 階層化された設定、ローカライズされた出力、アクセシビリティ設定、進捗報告、ステージごとの所要時間、バージョン管理されたJSON形式の結果または診断、
- 単体テスト、ビヘイビアテスト、統合テスト、プロパティテスト、スナップショットテスト、および初期段階のKani検証によるカバレッジ。

beta3リリースは、依存関係のみのアクションおよびターゲットの集約にも対応しています。空でない
`deps`リストを持つノードはレシピを省略できます。

## リリースと開発状況

v0.1.0-beta3リリースは、早期採用者にとって有用なプレビューであり、Netsukeが完成した、あるいはすべてのインターフェースが安定していることを宣言するものではありません。コンパイラパイプラインと通常のローカルビルドのワークフローは十分な内容を備えていますが、コマンドラインインターフェース、設定用語、高度なレシピモデルはまだ安定前の状態です。

自動化では、Netsukeのバージョンを固定してください。1.0までの間に、一部のコマンド名、フラグ、診断のスキーマ、マニフェストの詳細が変更される可能性があります。

以下の制限がbeta3に適用されます。

既知の制限には、以下が含まれます:

- レシピは依然としてシェル文字列のままです。Unixのスクリプトは
  `/bin/sh -e`を使用し、WindowsのレガシーレシピはデフォルトでWindows
  PowerShellを使用し、Windows
  Bash互換ルートは明示的なオプトインです。構造化された実行ファイルの引数やレシピの環境マッピングはまだ実装されていません、
- GCCのdepfileのようなコンパイラ生成の依存関係インポートは計画されていますが、まだマニフェストモデルには含まれていません、
- `--json`は各コマンドに対して正確に
  1つのバージョン管理された結果または診断ドキュメントを出力しますが、そのスキーマは1.0までに変更される可能性があります、
- 色付けの描画は実装されていません、
- アクセシビリティは支援技術による検証がまだ必要です。

beta3リリースは、Ninjaを意識したエスケープ処理によってbeta2のシェルドル記号に関する制限を修正したため、通常のシェル式を普通に記述できるようになりました。リテラルなシェルドル記号の式を使用しているbeta2のマニフェストは移行が必要です。詳細は
[ユーザーズガイドの安全境界](docs/users-guide.md#review-the-safety-boundary)
を参照してください。

`Netsukefile`はコマンドを実行し
、副作用のあるテンプレートヘルパーを使用できます。`Makefile`と同様の注意を払い
、信頼できないマニフェストは実行前にレビューしてください。Netsukeはサポートされるパスの置換をクォートしますが、サンドボックスではありません。

## 今後の展望

最初のリリース後の作業は、3つの優先事項を中心に構成されています:

1. **コマンドライン契約の安定化**:正規のコマンド名とフラグ名、非対話的な保護機構、安定した終了ステータス、範囲が制限された出力、バージョン管理された
   `--json`ドキュメントを堅牢にします。
2. **レシピをより安全で明確にする**:構造化された実行ファイルの引数、環境マッピング、コンパイラの依存関係インポート、条件付きアクションに関するより良いフィードバックを追加します。
3. **信頼性の強化**:Kaniとプロパティテストのカバレッジを拡大し、支援技術によるアクセシビリティの検証を行い、ターミナル描画のリグレッションカバレッジを追加します。

より長期的な作業では、機械可読なコンテキスト、プロファイル、実行履歴、成果物の配信、人間とエージェントのワークフロー向けのローカルファーストなフィードバックについて検討します。詳細な順序と現在の進捗は
[ロードマップ](docs/roadmap.md)で確認できます。
